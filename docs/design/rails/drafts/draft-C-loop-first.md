# Draft C — Loop First

*One of three independent designs for the rails. Angle: the operator↔session loop is the first quality gate and the largest cost; every engineering gate hangs off a loop step so it cannot be skipped. Written 2026-10-05 against the evidence in this scratchpad. Process language only; no household data.*

## 1. Thesis

The defects that reached the operator were not caught by the build because nothing in the build was *attached to the moment the operator would have caught them*. The operator caught 27% of fixes on real data, CI 8%; 35% of the operator's messages were approve/push/merge ceremony, and the largest operator-caught classes were "built the wrong thing" (170), "said done but the screen disagreed" (111), "wrong domain fact" (102), "stopped instead of acting" (88) and "statement with nothing behind it" (52 + 251 agent retractions). Those five are loop failures, not code failures, and they happened at the three moments no hook intercepts: the first commit, the sentence that claims something, and the end of a turn. This design makes those three moments the gates. A session reads its intent back before it may commit (PreToolUse deny on `git commit`); it may not end a turn on an offer, a done-claim without a walk artifact, or an existence/absence claim without a receipt (Stop hook, `decision: block`, once per turn); it pushes, opens one PR per line of work and arms auto-squash without asking (git pre-push hook, PreToolUse deny on a second `gh pr create`), and the operator's only word is `hold`, detected by the one hook that can tell the human's text from the agent's (UserPromptSubmit). The engineering gates for layers 1, 4 and 7 — boot the real root, root and env parity, the real-data golden checker, gate manifests with required-by dates — are then attached to loop steps (pre-push, PR open, milestone close) so that skipping them is not a choice a session can make. Everything else that cannot fail is deleted: the primer, the phase nudges, the 17 commands, the prose rules, the 9,160-word CLAUDE.md, the retro-debt nag. The ceremony per PR falls from roughly five operator messages to one — the intent acknowledgement — and that one is the message the evidence says was missing.

## 4. Templates

Doc templates are the few that caught defects in the audits: short, checked against code, each section consumed by a gate. Code templates are the starter kit. CI templates are the workflow skeleton and the manifest.

## 5. Governance

**Admission.** A rule, hook, template section or CI job enters the harness only as a row in `ci/gates.toml` with: the incident or defect class it cites (sha, issue, or transcript class), its planted defect (a path to a test that turns it red), its false-positive count on the current tree at landing, one case from outside its own list, an OS/shell case (backslash path, PowerShell twin), and either `required_by` (for CI jobs: the date it joins `gate.needs`) or `delete_by` (for advisory hooks: the date by which the ledger must show a catch). `test_gates_manifest.py` fails a PR that touches `ci/`, `.github/`, `.claude/` or the plugin without a complete row. A prose rule enters CLAUDE.md or the contract only with `→ enforced by: <path>` on the same line; `test_rule_admission.py` rejects the diff otherwise. Judgment lives under `## Judgment`, capped at 40 lines, and is the only prose exempt from the pointer.

**Retirement.** The ledger (`ci/mechanism_ledger.py`, schedule lane) tallies per mechanism id: runs, findings, defects, false positives, from the Mechanisms tables of merged PRs and from hook firing logs (`${CLAUDE_PLUGIN_DATA}/rails/log.jsonl`, one line per fire with verdict when known). Three rules, all printed at session start and none requiring a reader: (1) a CI job past `required_by` and not in `gate.needs` fails every PR until it is required or deleted — the question on red-at-arrival is *which*, never "leave it reporting"; (2) an advisory mechanism with ≥20 fires and 0 defects over 30 days gets a `delete_by` 14 days out, and the manifest test fails once that passes with the mechanism still registered; (3) a deny hook whose override token appears in more than half of the sessions it fired in is flagged `teaches-bypass` and must be re-scoped or deleted (the `pr_body_check` lesson: 49 `--admin` merges). Extensions need a written reason in `gates.toml`, the rule CLAUDE.md already has for closing by hand.

**Context budget.** Hard: CLAUDE.md ≤150 lines (~1.5K words, ~2K tokens); `session-contract.md` ≤600 words (~0.8K); every other `.claude/rules/*.md` carries `paths:` (the CI section becomes `.claude/rules/ci.md` with `paths: [.github/**, ci/**]`, the fleet section `.claude/rules/fleet.md` with `paths: [deploy/**]`); MEMORY.md index ≤60 lines (~1K); skill descriptions ≤1,536 chars total; `rails_state.py` ≤1,500 tokens, self-measured. Target preload: **≤6,000 tokens** of repo-specific context before the first action, against 21–24K today. Subagents run `omitClaudeMd: true` unless they need it. Enforced by `test_context_budget.py` (file sizes, in CI) and the state hook logging its own size (surfaced by the ledger).

**Harness as product.** The harness repo is the plugin: one checkout, loaded in place through a local-path marketplace with a relative-path source (recon §3.9), so every worktree and every repo reads one copy and no version bump is needed. The repo holds only wiring (`.claude/settings.json` hook registrations pointing at `${CLAUDE_PLUGIN_ROOT}`), repo-specific lists (`gates.toml`, `concepts.toml`, `env.manifest.toml`) and `ci/`. `test_scaffold_matches_plugin.py` (baseline-then-drain, the `contract_gate` landing pattern) fails when the repo's wiring drifts from the plugin's `hooks.json`. jarvis `scripts/apex-port/` is deleted; two copies was the bug.

**Measurement.** Weekly, from git and `gh`, never hand-kept: fix share of commits (baseline 36%), automation catch rate (fixes whose first detector was CI/hook/walk: ~10%), ceremony share of operator messages (35%), correction share (14%), time-to-first-operator-catch per release, and the gate-precision table (real / harness / infra per job). The classifier that produced this evidence runs on schedule and prints deltas at session start.

## 6. The session contract (layer 9)

This is the one page that resolves the conflicting rules. It is the only always-loaded prose besides CLAUDE.md, and every clause names its enforcer. Text as it would ship in `.claude/rules/session-contract.md` (≈520 words):

> **1. One line of work.** You hold one claim: one issue or milestone, one worktree, one branch, one PR. Slices are commits. A second `gh pr create` for this worktree is refused (`pr_create_gate`). "One active front" means *your* claim; it is never a reason to stop. If your line is blocked, write the blocker as a decision brief (problem, options with costs, recommended option first) and continue on the next unblocked item of the same line.
>
> **2. Read intent back before the first commit.** Write `.rails/intent.json` — builds, does not build, retired paths, screen of record, target, acceptance lines with door and instrument, clocks, concepts, silent defaults — and end the turn showing it. `git commit` is refused until the operator's next message arrives (`commit_intent_gate`; the ack is the human's message, any message). The operator may say `hold`; silence after the ack is consent for everything below.
>
> **3. Push, open, arm. Do not ask.** Every commit is pushed (`pre-push` refuses only `.rails/hold`, a missing intent, or a leak). When the slice is coherent, `rails pr` opens the one PR, arms auto-squash and binds the monitor. The operator's only word is `hold`; `release` lifts it. There is no approve step. The old consent variable is gone.
>
> **4. CI is watched by the monitor, not by anyone.** Red or conflict wakes *this session*. You diagnose with `run_triage` first, fix in a commit, and never ask the operator to look.
>
> **5. Statements need receipts.** A sentence that says something exists, is absent, is deployed, or caused a failure cites a receipt made this turn (`rails receipt`, `rails where-is`). Memory and issue bodies are reports; re-run before repeating. The turn-end gate blocks a claim-shaped sentence with no receipt this turn.
>
> **6. Done is a walk, not a sentence.** "Done", "fixed", "working", "ships" are refused at turn end unless `.rails/walk/<HEAD>/steps.json` passed on `intent.target`. A fixture, mock, dev harness, `/dev/login` or standalone root is not the target. Frames stay on this machine.
>
> **7. A turn ends on work, a receipt, or a brief — never on an offer.** "Want me to…", "say the word", "let me know" are refused while `.rails/work.json` has open items. A real decision is a brief with a recommendation and proceeds unless the operator says otherwise.
>
> **8. The operator's correction is written into the artifact it corrects** — intent, design, milestone, issue — in the same turn. Chat dies at compaction.
>
> **9. Household data never leaves the box.** Not in git, CI, issue or PR bodies, subagent prompts, or the walk summary. The pre-push leak check is on by default; the walk writes ids, never values.
>
> **10. Rules are mechanisms or judgment.** A rule you want to add ships with its enforcer in the same PR or goes under `## Judgment`. Anything in CLAUDE.md or memory that contradicts this page is wrong; delete it.

**Enforcement map.** Clauses 1, 3, 4: `pr_create_gate`, `pre-push`, PR monitor. Clause 2: `commit_intent_gate` + `rails_prompt.py`. Clauses 5, 6, 7: `turn_end_gate.py`. Clause 8: advisory — the only unenforced clause; the retro asks whether a correction this session reached an artifact, and the ledger counts "correction with no artifact" from transcripts. Clause 9: `pre-push` leak check, `secret_*` gates, `.gitignore .rails/walk`. Clause 10: `test_rule_admission.py`; a SessionStart grep of MEMORY.md for retired phrases (`never push without asking`, `ask to merge`, `arm and stop`) prints a delete notice.

**Ceremony per PR under this contract:** one operator message (the intent ack, often the same message that redirects scope), optionally `hold`. No push approval, no PR approval, no merge approval, no "did you refresh", no CI watching. Today's measured equivalent is ~2.2 ceremony messages per new-work message plus 339 bare approvals.

**How the turn-end gate tells "work remains" from "a decision is needed".** `.rails/work.json` is derived from the acceptance lines at intent time (one item each) plus items the session adds. An item closes only with a pointer to a receipt (`walk:<step>`, `test:<id>`, `receipt:<n>`) and the hook verifies the pointer resolves. An item may instead be marked `decision` with a brief; a turn ending on a brief is allowed. The hook blocks once (`stop_hook_active` false), then lets the second attempt through with `additionalContext` naming what was skipped, so it can never loop and the skip is visible in the transcript and the ledger.

**Coordinator for concurrent sessions.** Nine worktrees were live on one day; the operator relayed ~124 messages in two periods. The claim store (jarvis `_claimstore.py`, under `CLAUDE_CONFIG_DIR`, keyed on the main checkout) grows four tables: open PRs with files touched (5-minute `gh` cache), red-master owner (first session to run `run_triage` on a master red claims it; others see "master red, owned by <leaf>"), `hold`, `used`. `rails_state.py` prints the overlap: "your claimed files are also in PR #N (session <leaf>)". When the file-touch index shows overlap between two open PRs, the second PR's monitor runs `gh pr update-branch` after the first merges, so CI re-runs on the merged tree (PR-20 for the conflicts the index can see). Cross-session messages use `SendMessage` to the named session; the operator stops being the bus.

## 10. Where this design is weakest

1. **The turn-end gate judges text.** Deterministic triggers on done-words and offer-shapes are gameable by rewording, and the published reward-hacking result says optimisation against a monitor produces behaviour that does not trigger it. The mitigations are structural (the work list closes only with receipt pointers that resolve; the walk file must exist at HEAD) but the work list is maintained by the agent. If the ledger shows the second-attempt pass-through being used on more than ~20% of blocked turns, the gate has become signage and should be re-cut to block on *artifacts only* (no text matching at all), with the operator reading the skipped-count at session start.

2. **Layer 4 is attached, not designed.** The golden checker and concept registry are loop steps with real enforcers, but the ontology itself — which rules, which worked examples, how the operator reviews them without amounts entering a prompt — is specified only as the rulebook template and the approved-ids file. An angle that starts from the semantic layer would do this better; this draft's contribution is where the check *must run* (before close, on the operator's store, ids only), not what it contains.

3. **Layer 5 leans on reachability from roots.** AST reachability plus `reachable_by: walk-step` closes the `__init__`-import hole, but a module reached from a root through a registry lookup by string will read as unreachable, and the exemption path (`reachable_by`) is where the next false "wired" claim will live. The outside-list case in the manifest is the only guard.

4. **Boot-smoke cost is estimated, not measured.** 4–8 minutes assumes the `image` job's artifact is reusable and the fleet starts in under two minutes on a hosted runner; `fleet_smoke` today has a 30-minute timeout. If the measured cost is over 10 minutes per PR, the job should run only on the paths that change a root or a seam, and the manifest's FP count decides whether it stays required.

5. **The coordinator is files, not a service.** Claims, overlap and red-master ownership live in a directory under `CLAUDE_CONFIG_DIR` written by hooks; two sessions writing in the same second can race, and a session outside this machine (web, cloud) sees nothing. The `SendMessage` wake-up depends on the desktop environment. PR-20 is therefore partial, and the twice-daily schedule remains the real backstop for semantic conflicts.

6. **One ceremony message remains, by design.** The intent ack costs one operator message per line of work. If the operator finds even that too heavy on small fixes, the gate should accept a pre-grant in the *dispatch* prompt (detected by `UserPromptSubmit` as the first human message) so that a fix session with a one-line task skips the read-back; this draft does not specify that path because the evidence says the read-back was the message most often missing.

7. **Receipts prove a command ran, not that its output means what the sentence says.** A `where-is` that searches the wrong tree still produces a receipt. The identity line (`current_user`, host, cwd, tree) beside every receipt is the only defence, and it is exactly the probe-in-the-wrong-place class the transcripts show.

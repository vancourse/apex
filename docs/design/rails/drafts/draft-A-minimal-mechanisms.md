# Draft A — Minimal mechanisms

Designer angle: the smallest set of blocking mechanisms that covers the largest share of the 1,007 escaped defects and the operator-caught mistake classes; everything that cannot fail is deleted. Written 2026-10-06 against `evidence_report.md`, `coverage_matrix.json`, `process_requirements.json`, `anti_patterns.json`, `transcripts_report.md` (dedup counts), `ci_analysis.json`, `harness_inventories.json`, `doc_audits.json`, the three research briefs, and the live trees of `apex` (`1b1f4e8`) and jarvis `origin/master` (hook registrations and `gate.needs` read 2026-10-06).

## 1. Thesis

Only four things in this toolchain can refuse: a `PreToolUse` deny, a `Stop` block, a GitHub required check, and a git hook. Everything else — CLAUDE.md, memory, primers, skills, nudges, review logs — is context, and the evidence says context does not bind: 22 of 32 CLAUDE.md rules are prose-only, 35% of corrections repeated a written rule, apex's phase nudges were followed 13% of the time, and the one prose rule a session quoted three times was broken four turns later. Meanwhile the seam family (wiring 15.7%, deploy/config 10.5%, contract drift 8.9%) did not move between nexusiq and jarvis, and the single instrument aimed at it — booting the real composition root — runs on a schedule and gates nothing. So this design spends its whole budget on seventeen mechanisms that occupy those four slots, each named for the defect class it stops, each with a planted defect, a measured false-positive count and a required-by date, and it deletes everything in apex, CLAUDE.md and the jarvis hooks that has no firing record. The operator's side is inverted the same way: a session loads at most 1,500 words of standing prose, the push/PR/merge ceremony is replaced by two artifacts per line of work (an intent read-back before the first commit and a walk receipt at the end), and "done" for a release means the operator used it, recorded as one comment. Fewer mechanisms, each of which can fail, each of which is read where it fires.

## 2. The process on one page

Each step names the gate that holds it. A gate is one of: `deny` (PreToolUse, `permissionDecision: "deny"` or exit 2), `stop` (Stop hook, `decision: "block"`), `req` (GitHub ruleset required check `gate`), `git` (pre-commit / pre-push via `core.hooksPath`). Steps marked `prose` have no gate and say so.

0. **Session start.** The `rails-state` SessionStart hook prints state only, ≤ 60 lines: your claim, the WIP front, any `hold`, pending receipts (intent, review, walk, use), finished-but-unused milestones, the last scheduled-lane result. No prose, no primer. — gate: none (SessionStart cannot block); its size is pinned by `test_context_budget.py` (`req`).
1. **Claim the line of work.** `rails claim <issue|milestone>`. The claim store enforces the WIP limit (`wip.apps = 1`): a second app's milestone cannot be claimed while the first app's latest milestone has no use receipt. — gate: `deny` on the first `Edit|Write` of a source path with no claim (M12a).
2. **Read intent back.** Write `.rails/<worktree>/intent.md`: building / not building / retired paths that must stay dead / screen of record (file) / acceptance lines, each naming its door and instrument. It is shown to the operator in the first turn; silence proceeds, `hold` stops. — gate: `deny` on `git commit` (Bash and PowerShell) while `intent.md` is absent for this worktree (M12b).
3. **Spec only when ambiguous.** If the intent file cannot carry it (a seam table, a new concept, a model in the loop, a trust boundary), write one page in the living `spec.md` as a dated amendment. A vN never gets a second document. — gate: `prose` for the decision to write one; `req` for its shape (placeholder text fails `test_no_stub_sections`).
4. **Build walls first.** Contract source (`contracts/`) → generated DB models, API models, TS client; settings declared once in `env.toml`; the composition root wires every seam explicitly and calls `assert_no_null_seams()`. — gate: `req` `checks` job: codegen `git diff --exit-code`, identifier-registry test, `response_model` lint, must-use-result lint, clock lint, concept-owner gate (M2, M5).
5. **Test honestly.** Database tests run as the production role through the production factory and print identity; planted data exceeds every limit, has two households and a non-UTC member; engine tests run under two pinned clocks; changed lines are mutation-checked. — gate: `req` `suite` job plus the `mutants` step (M4).
6. **Run the local gate.** `rails check` (the reworked `ci/pre_pr_check.py`) runs CI's own commands cheapest-first on the merge tree and writes `.rails/<worktree>/check-<HEAD>.ok`. — gate: `git` pre-push refuses without a marker for HEAD, and runs the store-backed leak check (M13, M18).
7. **Cold review.** `rails review` dispatches fresh-context reviewers (two voices on seam paths, one otherwise, two rounds max) and writes `.rails/<worktree>/review.json` with the diff hash; every must-fix becomes a commit or an issue with a falsifiable done-when. — gate: `deny` on `gh pr create` and `gh pr ready` while `review.json` is missing or its hash is stale (M9, M12c).
8. **One PR per line of work, armed.** `gh pr create` is allowed once per worktree; the hook's `additionalContext` carries the body sections and the arming command; the turn cannot end while the PR lacks `autoMergeRequest` or a bound monitor. — gate: `deny` (second open PR) + `stop` (M12c, M12d).
9. **CI judges the merged behaviour, not the prose.** `gate` requires `classify`-free `checks`, `suite`, `boot-check`, `walk`, `image` (path-filtered, `if: always()` aggregation kept). — gate: `req` (M1, M7).
10. **Done is a walk receipt.** For any route- or screen-facing item, run `rails walk <target>` at the merged SHA on the named target (dev fleet or the local real-data preview); it writes `.rails/walk/<sha>.json` plus frames. The work item is marked `done` with that path. — gate: `stop` blocks a `complete` with a done item lacking an artifact (M12d).
11. **Release close = used.** A milestone closes only with (a) the walk receipt at the closing SHA, (b) `rails oracle` reporting zero violations on the operator's own store (rule ids and row ids only), and (c) the operator's `used: <task> <date>` comment. — gate: `deny` on the milestone-close API call from a session without all three; the operator's own hand in the web UI is the escape hatch, by design (M12e, M6, M15).
12. **Retro = a row in `gates.toml` or nothing.** A lesson enters the harness only as a gate, hook or lint with its planted defect, FP count and required-by date; otherwise it is dropped. — gate: `req` `test_gates_registry.py` (M10). The `retro_due` debt nag is deleted.

What the operator does per line of work: reads one intent read-back (optionally says `hold`), reads one done receipt. Per release: uses the app once and leaves one comment. Nothing else is waited for.

### 3.1 Notes on the load-bearing ones

**M1 boot-check** is `ci/fleet_smoke.py` promoted and widened, not a new job. Sequence: `test_env_parity.py` (static, seconds, fails before Docker starts) → build or pull the image from the `image` job → for each composition root declared in `rails.toml` (`fleet`, `standalone`, `desktop`, `cli`): migrate a database created at the *previous release's* schema, boot, boot again, connect as `NOSUPERUSER NOBYPASSRLS` through the pooled factory, then one request per registered route (asserting on body, because the SPA fallback 200s everything — `fleet_smoke.py:53-60` already knows this), one navigation per nav item, one tick per schedule, one message per produced topic. Root parity is derived: the fleet root's config fields, protocols, schedules and env names are introspected and every other root must carry each or name it in `root_exclusions.toml` with a reason. `assert_no_null_seams(root)` is a kit function the root calls at the end of `build_root()`; a `None`/no-op seam in a production root is a boot failure. It is the single mechanism that covers wiring, deploy/config and built-not-wired — 130 defects by earliest catch plus 41 gaps — and it is the one the current harness runs on a schedule nobody reads (red 37 consecutive runs while master was green). Required from day one with `required_by` set, per M10; measured FP count on the current tree before it enters `gate.needs` (today it is red on master because a boot gate refuses the smoke's synthetic env — that is the first FP to fix).

**M2 one-source contracts** keeps what works (Pydantic wire models → `frozen.json` → TS, diffed against the merge base, 75 commits since 09-01, "the clearest case of contract-first working") and adds the missing halves: the DB models are generated from or checked against the same declarations (a `test_ddl_matches_contract.py` comparing SQLAlchemy/DDL column sets to the wire model fields marked `persisted`), every identifier that crosses a component (event name, topic, enum value, authority, health vocabulary, route path) has one declaration in `contracts/registry.py`, and `test_identifier_registry.py` asserts every emitter has a subscriber and every subscriber a publisher, every UI state can be produced by the engine, and every attribute the executor reads exists on every registered tool. Unmatched identifiers raise. Two lints ride in `checks`: a FastAPI route without `response_model` fails (23 Hearth routes bypassed it, #2326), and a load result consumed without matching its error branch fails (`eslint-plugin-neverthrow`-style `must-use-result`; `?? []`/`?? 0` on a load result is an error — #2240's 42 of ~90 sites).

**M4 test honesty** is mostly a default flip: the kit's `conftest.py` creates the schema as owner and *connects* as the production role, printing `current_user, rolsuper, rolbypassrls, current_setting('app.tenant_id')` in every DB test's output; a census test fails on any fixture that connects as superuser unless it is in `superuser_allow.toml` with a dated reason (baseline-then-drain, the `contract_gate` landing pattern). Mutation runs incremental on the diff's files (mutmut for Python, Stryker `--incremental` for TS), 1–5 minutes, and a surviving mutant fails the step unless listed in `mutants_allow.toml` with a date — Google's "surface on changed lines in review" shape, not a score target. The evidence for the planted-dataset rule is `LIMIT 2000` dropping 56% of rows and a 30-row fixture that collapsed to 17: the kit's planted dataset asserts its own landed row count and that it exceeds every constant in `limits.py`.

**M5 and M6 together are layer 4.** The concept registry is Vernon's "one owner per invariant" as a table the arch gate reads: `concepts.toml` rows (`income`, `spend`, `liquidity`, `ledger_frontier`, `month_arith`, `account_role`, `fx`, `settlement`) each name the owning function and its pinning test; `check_concept_has_one_owner` fails any module outside the owner that re-implements the pattern (an explicit pattern list per concept, with the required out-of-list case from PR-12). The clock lint forbids `datetime.now()`/`date.today()`/`Date.now()` outside `clock.py`, which names four clocks: `data_frontier`, `wall`, `pinned_as_of`, `member_tz`. The oracle is approval testing with the privacy constraint built in: the operator approves worked examples once (the "Measured-on / Refused-by" table shape from the trips rulebook, which was the most defect-aware document in the corpus), the file lives outside git, the checker prints only rule and row ids, and CI runs the identical checker on the planted dataset so the parity property ("a card equals the sum of its drill rows; every surface showing a concept agrees") is exercised on every PR while the real-data run gates the close.

**M7 walk** generalises the Purser walkthrough, which is the one gate here that caught honesty regressions every unit test survived. Three rules carried over from its failures: text and effect, never pixels or geometry (216 Sherpa failures, 0 defects); the dated corpus and the server share one pinned `as_of` (the 101-run time bomb); frames are artifacts for the operator's walk, not assertions. New rows: a stub client that *rejects*, 503s and times out so the transition is exercised (design-gui §6 specified every state and #2240 shipped anyway); back/reload; 375 px `scrollWidth`; the household-vocabulary scan extended to release ids and rule ids. The same script is the done receipt: `rails walk dev-jarvis` or `rails walk preview` at the merged SHA writes `.rails/walk/<sha>.json`.

**M9 cold review** is the only mechanism in this design whose core is judgment, and it is here because it is the one advisory practice with a measured yield (#2413: 46 reviews, 9 distinct must-fixes; #1580: two STRIDE passes, three findings neither held alone) against published averages that are poor (12 of 13 review agents below 60% signal). Three constraints keep it from becoming the unbounded design loop: reviewers get the diff and the primary artifacts it touches, not the author's reasoning; two rounds; and it is judged against code — a design reviewed before code gets one authoring pass and one adversarial pass, then build. The blocking half is a file, not body prose (anti-pattern 14): `gh pr create` is denied while `review.json` is missing or its `diff_sha` does not match the branch diff; a hotfix path exists (`rails review --single` for a one-file change) and is itself a row in the Mechanisms table.

**M12 session contract** is the layer-9 answer and the one place the conflicting rules resolve (§6). It reuses the claim store (`_claimstore.py`: keyed on the main checkout path under `CLAUDE_CONFIG_DIR`, identity is the worktree leaf) as the home for `intent.md`, `work.json` and `review.json`. The Stop gate reads structure, not sentences: `work.json` items carry `status ∈ {open, done, dropped}`, a done item needs `artifact`, and a turn may end with open items only if `stop_reason ∈ {decision_needed(brief), blocked(receipt), hold}` is set — a `decision_needed` requires a brief with a recommended option; a `blocked` requires the command or file read that proves the block. "Offer-shaped endings" are therefore not regex-matched; they are impossible without writing a stop reason the operator will read.

## 4. Templates

### 4.1 Documents (three; everything else deleted)

**`spec.md` — one living spec per component, amended with dated entries.** Replaces `prd.md`, `design.md`, `impl-plan.md`, `recon.md` and the eight-stage dossier (75 of 190 platform dossier files and 23 app stage files were unfilled stubs; no classified defect traces to overlap scans, OSS scans, freeze records or per-revision snapshots). Sections, each a table a test can read:

1. *Scenarios* — numbered, each with an acceptance line naming its **door** ("through the app, fresh fleet install, as a household member, no CLI") and **instrument** (DB role, factory, DB state, data set, client). The vocabulary is closed (`instrument ∈ {real-backend, planted, operator-store}`; `mock`, `dev-login`, `standalone` are allowed words but cannot be linked to a walk receipt, so they cannot close an issue).
2. *Seams* — value crossing a component or trust boundary · who stamps it · who trusts it · invariant · the test or gate that holds it. (Would have named the envelope tenant #362, the authority vocabulary copies, the two cookie policies.)
3. *Concepts* — rows that become `concepts.toml`.
4. *Clocks* — which of the four clocks each figure, producer and tool uses.
5. *Screen × state matrix* — rows loading / real-empty / load-failed / write-failed / 401 / 503-disabled / not-mounted / partial / 375 px / back-reload, each with the visible text; becomes the walk's stub-client rows.
6. *Failure modes* — what fails · user-visible behaviour · **detected by** (`nothing` is allowed and auto-becomes an issue); one liveness row.
7. *LLM seam* (only when a model is in the loop) — context inventory, write authority (user-authored stores read-only in the tool layer, with the test named), loop budget, determinism boundary, output strip-list, acceptance against a recorded or live call.
8. *Premises* — vendor/platform semantics asserted: premise · measured on version · command · result.

## 5. Governance

**How a mechanism earns its place.** A row in `ci/gates.toml`:

```toml
[[gate]]
name = "boot-check"
kind = "ci_job"                 # ci_job | hook | lint | git_hook | arch_check
prevents = ["wiring_integration", "deploy_env_config", "data_persistence"]
cites = ["e854e76289", "c26832080a", "7f98347cd3", "#2245", "#2270"]
planted = "ci/planted/boot_check_null_seam.py"   # a test that turns it red
fp_count = 1                    # measured on the real tree before enabling
fp_measured_on = "2026-10-13"
required_by = "2026-10-20"      # in gate.needs by this date, or deleted
```

`test_gates_registry.py` (in `checks`, sub-second) fails when: a job in `ci.yml` has no row; a hook in `hooks.json` has no row or no fixture with a `C:\` path and a PowerShell payload; `required_by` has passed and the job is absent from `gate.needs`; `planted` does not exist or does not fail when run against the gate; a `kind = "prose"` row is older than 30 days. The planted-defect rule is the one CLAUDE.md already states and the CI data shows was never applied (Windows scheduler red 7 of 7 on day one, Install Chromium 20 PRs in 2 days, PR-body policy 27 branches in a week); as a test it fires.

**How it is retired.** A scheduled reporter (not a gate — scheduled reds are read by nobody: 20 of 20, 37 consecutive) writes `ci/gate_yield.json` from the Mechanisms tables and CI logs: catches per gate per 30 days. The SessionStart state prints the rows with zero catches in 60 days and no `cites` added. A zero-yield row is deleted or re-justified in a PR; `test_gates_registry.py` fails when a row's `fp_measured_on` is older than 90 days without a `yield_reviewed` date. Hooks keep the same rule: `reuse_inventory.py`, the one advisory hook kept, has `required_by = 4 weeks` to show a measured follow-through (a design change traced to its injection) or it goes. The two numbers to watch are the ones the evidence names: share of job failures that are harness defects (44% today; target < 10%), and share of red runs containing a real product defect (22% today; target > 60%).

**Require-or-delete for CI jobs.** No job may run in "reports, does not block" mode without a `required_by` date within 14 days (101 of 101 and 102 of 102 red runs happened in exactly that mode). A non-required job red on 3 consecutive runs appears in the SessionStart state as a line the next session must act on — make required or delete — and `required_by` failing on the 7th day makes `checks` red for everyone, which is the point.

**The context budget.** 1,500 words of standing prose, pinned by `test_context_budget.py`. CLAUDE.md carries only commands needed at the moment of typing them and judgment rules with no mechanism (today's CLAUDE.md is 32% CI facts and 18% front log — both move: CI facts into `.claude/rules/ci.md` with `paths: [".github/**", "ci/**"]` so they load only when touching CI, the front log into the SessionStart state generated from milestones). The measured preload today is ~21–24k tokens (CLAUDE.md ~15k, MEMORY.md ~4.6k, SessionStart ~2.7k); the budget here is **≤ 6,000 tokens** before the first action: CLAUDE.md ≤ 2,000, SessionStart state ≤ 600, always-loaded rules ≤ 700, skill listing ≤ 400, MEMORY.md ≤ 1,500 (≤ 100 lines; checked by the SessionStart script since CI cannot see user files, printed loudly when exceeded). The ETH result (repository overviews: no success gain, +20% cost) and Anthropic's own "if you emphasise many lines, none stands out" are the warrant; the measured regrowth from 1,962 to 9,160 words in seven weeks is why it is a test and not a rule.

**A rule is admitted only with its gate.** The retro skill survives as the sole path into `gates.toml`; its ladder (gate/test > hook > drop) loses the "prose" rung. A lesson that cannot be a check is written into the PR body and dropped from the harness. Memory notes carry `verified_at`; nothing nags about it (anchoring reached 21% after seven weeks of nagging); instead the SessionStart script prints the count of notes older than 60 days as one line.

## 6. The session contract (layer 9)

The contract is one file the hooks read, `.rails/<worktree>/work.json`, plus `intent.md` and `review.json` beside it, all in the claim store outside the repo. It is where the conflicting rules are resolved, once:

| Conflict today | Resolution here | Mechanism |
|---|---|---|
| "Never push without asking" vs "don't wait for my go-ahead" | Push is allowed when the local gate marker exists for HEAD; the operator's word is `hold` (a file `.rails/hold` or the word in chat, which the session writes to the file). Consent is no longer per push. | M13, M12f |
| "Arm auto-merge, never poll" vs "how come you were not monitoring" | Arm auto-squash and bind the PR monitor (`ccd_pr set_monitor`) at open; the monitor wakes the session on red or conflict. The turn cannot end with an open PR that is unarmed or unbound. Polling is neither needed nor allowed. | M12c, M12d |
| "One active front" vs "do all of that work" | The front is the claimed milestone; `work.json` carries every item the operator named; a session stops only when every item is `done` with an artifact, `dropped` with a reason, or a structured `stop_reason` is written. "A posture says stop" is not a stop reason. | M12d, M15 |
| "One issue per session" vs release-scoping | The issue cap lives in the claim store: one defect issue per session unless the claim is a milestone being decomposed. | M12a |

**Read intent back before the first commit** (170 operator catches, the largest class). `intent.md` has five headings: *Building*, *Not building*, *Retired paths that stay dead* (checked by `test_retired_paths.py`, a grep gate generated from this list — "the retired enrollment path came back in 4 periods"), *Screen of record* (a file path; if the handoff has several files, the one its own `README`/§0 names), *Acceptance lines* (door + instrument). The session shows it in its first message; the operator reads one short block instead of correcting the result days later. The `git commit` deny is the forcing function; a `--amend`/`fixup` on a branch that already has an intent file passes.

**Statements need receipts** (77% of 645 self-corrections were wrong statements; 87% of claim errors had already reached someone). Honest status: mostly prose. What is mechanised: *done* is a walk artifact (M7, M12d); *deployed* is the deploy script's receipt (`run.ps1 update dev` prints target, SHA and time into `.rails/deploy/<sha>.json`, and the Stop gate accepts a deploy item as done only with it); *the gate refuses X* is a `gates.toml` row (so the false "pr_body_check refuses" claim becomes a failing test). What remains prose: claims of existence/absence/root cause. The design ships `rails whereis <term>` (searches code, docs, branches, open PRs, issue titles, vault item *names*, both Windows and WSL paths) so the receipt is one command, and the two-voice review is instructed to challenge any negative claim without a scope. A `type: prompt` Stop hook that grades the final message for unreceipted claims is listed as a candidate in §10, not adopted, because an LLM judge drifts and the monitor-evasion result says text-matching trains wording.

**Done is a walk artifact on the named target.** `rails walk <target>` at the merged SHA; `.rails/walk/<sha>.json` carries target, SHA, URL, frames, every asserted step. Fixtures, dev harnesses, `/dev/login` and the standalone root are instruments the spec vocabulary admits but a receipt cannot cite, so they cannot discharge a done item. Only 4 of 645 self-corrections came from looking at a screen; this makes looking the only way to finish.

**Gate the end of a turn.** The Stop hook blocks (at most twice, honouring `stop_hook_active`) when: a source file is modified and uncommitted (apex's one-shot nudge had 44% follow-through as advice; as a block it is a commit or a `wip` stop reason); a done item has no artifact; open items remain and no `stop_reason` is set; an open PR for this worktree is unarmed or unmonitored. The legitimate stop reasons are enumerated in the file, and `decision_needed` requires a brief in the shape CLAUDE.md already asks for — problem in one line, options with costs, recommended option first — so the "bare question" rule becomes a schema.

**Ceremony per PR.** None required. Pushes happen when the gate passes; the PR opens Ready with the body sections injected; auto-squash is armed; the monitor is bound. The operator reads two things per line of work (intent, walk receipt) and says `hold` or nothing. Per release, one `used:` comment. The 878 approvals and 630 git/PR messages in the dedup counts are the budget this frees.

**Many sessions, one coordinator.** The claim store already keys on the main checkout and refuses collisions; the SessionStart state prints other live claims. Relaying is replaced by `rails note <session> <text>` writing into the store, read at the other session's next SessionStart — not a message bus, a shared file, which is all a solo operator needs.

## 10. Where this design is weakest

1. **Layer 2 is thin by intent.** `intent.md` replaces the spec for most work and design review happens only on seam paths. Design flaws are 20% of defect origins; this design bets that the boot-check, the walk and the oracle catch the consequences cheaply enough that a short spec plus one adversarial pass beats 153k-word dossiers. If the judge panel's backtest shows design-origin defects that none of M1/M6/M7/M9 would catch, the fix is a mandatory `spec.md` §Seams for any PR touching two components, not more prose elsewhere.
2. **"Statements need receipts" is mostly prose.** Done and deployed have artifacts; existence, absence and root-cause claims have `rails whereis` and a review instruction. 77% of self-corrections were wrong statements, so this is the biggest operator-facing class left to judgment. The candidate mechanism — a `type: prompt` Stop hook grading the final message — is deferred because an LLM judge drifts and text-matching trains wording; it should be trialled report-only with a `required_by` date, under M10's own rules.
3. **The oracle needs the operator's time.** A concept with no approved worked examples has no oracle; the design asks for one 25-minute approval session per concept set. If that time is not given, layer 4 degrades to the planted-dataset parity test, which catches surface disagreement but not wrong domain facts.
4. **boot-check cost and flakiness.** 6–10 runner-minutes on most product PRs, with Docker, Postgres and a previous-release migration in the loop; `fleet_smoke` has a 67% harness-failure history. The FP-first rule and `required_by` are the defence; if it cannot be made ≥ 80% real-defect precise in two weeks, the design has no fallback for the 35% seam family other than the walk.
5. **The Stop gate can be lied to.** A session can mark an item `done` with a stale artifact or write `blocked` with a thin receipt. The walk artifact is tied to a SHA and a target, which bounds the first; the second is bounded only by the operator reading it. The hook also runs at most twice per turn (`stop_hook_active`), so a determined session ends the turn anyway — by design, to avoid loops.
6. **Windows specifics are verified for Python hooks, assumed for one rewrite.** `updatedInput` on the PowerShell tool and the exact `tool_input` shape for PowerShell and `Task` are fixtures to write in week 1; until they pass on `windows-latest`, the PR gate's auto-arming is `additionalContext`, not a rewrite.
7. **Deleting 35 skills and most of CLAUDE.md removes some true statements.** The lessons archive stays on disk; nothing loads it. If a deleted judgment rule's class recurs, the retro rung is a gate or a drop — never putting the sentence back.
8. **The governance loop has never run.** `gate_yield.json` and the first zero-yield deletion are promises until the 30-day mark; the evidence shows "no mechanism has ever been removed because the ledger said it did not pay". The metric that proves this design is not more of the same is a deletion, not an addition.

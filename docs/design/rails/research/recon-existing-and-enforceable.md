# Recon brief: what already exists, and what can actually enforce

Written 2026-10-06 for the rails design workflow: (1) what in apex and jarvis is reusable, reworkable, or dead; (2) which facilities in Claude Code, git and GitHub can *block*.

**Baselines.** apex `1b1f4e8` (0.6.0, 2026-08-15, no commits since). jarvis `origin/master` `8c9fef2a5` (2026-10-06) via `git show`; the main checkout is 2,219 commits behind after the 09-27 history rewrite. Installed apex plugin: **0.5.0** (`installed_plugins.json`: last updated 2026-08-13), so jarvis never ran 0.6.0. Verdicts quote `harness_inventories.json` (241 sessions / 1,000 PRs); my own observations are marked.

**Trap for the designers.** `git show origin/master:.claude/...` in Git Bash fails (`ambiguous argument 'origin\master;.claude\...'`): MSYS rewrites `ref:path` when the path starts with `.`. `MSYS_NO_PATHCONV=1` fixes it; any hook shelling `git show <ref>:<path>` here needs it.

### 1.8 Cross-cutting apex findings

1. Every advisory mechanism failed its one measurement except those that fire *at the moment of a cheap action and say something concrete* (`artifact_templates` gh half, format-on-save) and the one soft block (Stop nudge).
2. The two blocking hooks are the defective ones: `guard-destructive` false positives (unfixed 2 months), `scan-secrets` never fired. A wrong blocker teaches bypass; jarvis's deny hooks avoid this (§2.2).
3. Three hooks were dead for the whole jarvis period because of backslash paths, and fail-open hid it. A deny hook must announce its own absence, and the test suite must include the operator's OS.
4. Two sources of truth diverge by 88-450 lines per file pair. `plugin.json` pins `"version": "0.6.0"`, and the loading reference says a pinned version "keeps every user on the cached copy until its author changes the string"; non-official marketplaces do not auto-update by default. §3.9 gives the fix.

## Part 2 — jarvis mechanisms that demonstrably worked, and how portable each is

### 2.1 Hook wiring (`.claude/settings.json` on origin/master, 173 lines, 25 registrations, 23 scripts)

Every hook is `python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/<name>.py"`, some with `timeout: 15` and `statusMessage` (`:7-12`). Matchers: `SessionStart` ×4 (`:4-33`), `SessionEnd` ×1 (`:34-43`), `Write|Edit|MultiEdit` ×3 (`:45-63`), `Write` ×1 (`:64-74`), `Write|Edit` ×1 (`:75-85`), **`Bash` ×12** (`:86-140`), **`PowerShell` ×1** (`:141-149`, `secret_file_touch_gate` only), `Read|Grep|Glob` ×1 (`:150-158`), `UserPromptSubmit` ×1 (`:160-171`).

- **12 Python processes per Bash call** (one serial sample 2.1s; bare `python3` 131ms; hooks run in parallel per the docs, wall unmeasured). A template should ship **one dispatcher process** for all command-shaped gates.
- **11 of 12 Bash gates do not wrap PowerShell**, and the memory note recommends PowerShell as the workaround when `merged_pr_push_gate` errors in old worktrees — the documented remedy for one hook bypasses all of them. PowerShell carried 8.6% of `git push`/`gh pr` commands in September, 26 of 40 in October. The hooks guide says it directly: "also match `Bash|PowerShell` ... matching `Bash` alone is not enough".
- **Hooks are branch-local**: resolved from the launch worktree, so a repair reaches only branches containing it (36 `issue_cap` and 14 acceptance notices were still stderr-mute three weeks after the fix; `finished_milestones.py` exists only on origin/master). A plugin root or user-level path is the only way one copy serves every worktree (§3.9).
- `ci/test_hook_delivery_channel.py` (`:1-40`) reads `settings.json` and asserts every registered hook speaks on stdout JSON (planted defects M1-M4). **Port as-is**; add "every `Bash` matcher has a `PowerShell` twin".

### 2.2 The deny hooks — one design, seven instances (all PreToolUse, all `permissionDecision: "deny"`)

Common pattern, portable verbatim (`.claude/hooks/` on origin/master):

- **Deny on a positive match of a tokenised shape; fail open on anything unexpected** — "Fail-open and deny are split on confidence, not on convenience" (`session_pickup_gate.py:46-53`).
- **Quoted spans and heredoc bodies are invisible**, so a commit message *about* the trap passes (`pipe_mask_gate.py:25-30`).
- **The override is matched in the command TEXT**, because a PreToolUse hook runs before the command's shell exists (`pipe_mask_gate.py:36-40`, `:74`); env is also honoured (`:154`). Variants `JARVIS_*_OK=1`; `stash_gate`/`merged_pr_push_gate` use an in-command `# stash-ok` / `# merged-ok` "written where a reviewer sees it" (`stash_gate.py:49-52`).
- **The denial names the safe alternative** (`secret_env_gate.py:14-21`).

### 3.9 Distributing one copy to many repos (the apex–jarvis drift problem)

From the plugin docs:
- `hooks/hooks.json` has "the same shape as the `hooks` object in `settings.json`", referenced via `"${CLAUDE_PLUGIN_ROOT}/..."` (quoted; a shell word). On Windows "the substituted paths use forward slashes".
- **A plugin cannot ship CLAUDE.md** ("Claude Code doesn't load a `CLAUDE.md` at the plugin root") and its `settings.json` honours only `agent` and `subagentStatusLine` — "every other key is dropped". **`permissions.deny` rules and CI cannot travel in a plugin**; they need a scaffold into the repo's `.claude/settings.json` and `.github/`.
- `${CLAUDE_PLUGIN_ROOT}` is a per-version cache dir; durable state goes in `${CLAUDE_PLUGIN_DATA}`.
- **Versioning is the drift mechanism**: a pinned manifest version "keeps every user on the cached copy until its author changes the string"; auto-update is "off for every other marketplace" unless `autoUpdate` is set. That is how jarvis sat on 0.5.0.
- **The solo-developer fix**: a marketplace added from a local path with a relative-path plugin source "loads in place ... Your edits to the source directory take effect at the next session start or `/reload-plugins`, and you don't need to increase the version." One checkout, every worktree reads it live. `--plugin-dir` is the session-only form.
- `enabledPlugins` in committed `.claude/settings.json` "reaches everyone who clones the repository", but is not fetched onto a machine "unless its marketplace entry has a relative-path source".
- Plugin subagents cannot carry `hooks`/`permissionMode`; use `hooks/hooks.json`. Backslash component paths are rejected on macOS/Linux.
- The deferral shim (`run-python-hook.sh:46-53`) is the anti-pattern that produced two sources; the plugin should be the only source, the repo holding only wiring and repo-specific lists.

### 3.10 Windows specifics the design must carry

1. Shell-form hook commands run under **Git Bash if installed**, else PowerShell; `shell: "powershell"` or exec-form `args` are explicit. Every Edit/Write path arrives as `C:\...`.
2. Match `Bash|PowerShell` on every command-shaped gate (11 of 12 jarvis gates and all 4 apex Bash hooks miss PowerShell).
3. `python3` is the registered interpreter; two logged hook errors were "python alias" failures — the dispatcher should resolve `py -3`/`python`/`python3` once.
4. Python hooks need `ensure_ascii` or a UTF-8 stdout (cp1252 default); `_hooklib.emit` and `claim.py:46-56` carry the fix.
5. `MSYS_NO_PATHCONV=1` for `git show ref:path` or `/d/`-shaped arguments.
6. `core.hooksPath` works absolute (`C:\...\ci\hooks`) or relative; tracked hooks must be `#!/bin/sh`, executable bit preserved.
7. On Windows, "Yes, and don't ask again" approvals are saved to `.claude/settings.json`, not the local file — a committed-settings pollution risk.

## Part 4 — Load-bearing facts for the designers

1. **Only four things can fail**: a `PreToolUse` deny, a `Stop` block, a GitHub required check, a git hook. CLAUDE.md, memory, SessionStart text, skill prose and prompt nudges are context, and the docs say so. Layer 8 has exactly these four slots.
2. **The turn-end gate exists and is unused**: `Stop` + `decision: block` + `stop_hook_active`. apex's one-shot nudge is the only instance and had the best advisory follow-through (44%). Layer 9's "done is a walk artifact" is a Stop hook that looks for the artifact file.
3. **Deny hooks that stayed on share five properties** (§2.2): tokenised shape, quoted-span blindness, fail-open on uncertainty, command-text override, denial names the alternative. apex's two blockers lacked them. Reuse the jarvis code.
4. **The walls are half built**: wire DTO → frozen JSON → TS with a merge-base gate works; nothing derives the DB from it; `fleet_smoke` is the boot check but schedule-only; `seam_contracts` has 2 adopters. The decision is cost: `fleet-smoke` at ~30 min per PR vs 12h latency.
5. **Merge is bypassable** (admin bypass actor), **strict is off**, **merge queue absent**. The cross-PR conflict hole has three priced fixes: rebase per merge, a plan-gated queue, or the twice-daily schedule read by a SessionStart report.
6. **Context budget is not enforceable inside Claude Code**; the only mechanism is a CI test on file size plus `paths:`-scoped `.claude/rules/`. jarvis is at 9,160 words against a 200-line target; its 2,844-word CI section is the first `.claude/rules/ci.md`.
7. **One copy, many repos**: a local-path marketplace with a relative-path plugin source loads in place, no version bump. Plugins cannot carry `permissions.deny`, CI or CLAUDE.md, so the template is plugin (hooks, skills, agents) + a scaffold into `.claude/settings.json`, `.github/`, `ci/` + a CI test that the scaffold matches the plugin (baseline-then-drain).
8. **Every hook needs a PowerShell twin and a backslash fixture**; the missing-script case needs a dispatcher that is never missing (plugin root), prints a loud `additionalContext`, exits 0.
9. **Delete from measurement**: apex primer, prompt/edit/security-path nudges, `session_output_gate`, all 17 commands, ~25 unused skills, 5 of 6 rule files, `pr_body_check` as CI, `retro_due` debt count, `discovery_dossier` nudge, user-level duplicate skills. **Keep**: the two-voice freeze reviews, `python/typescript-review`, format-on-save, `artifact_templates` gh half, `issue_cap`, the jarvis deny hooks, `claim.py`, `reuse_inventory`, `test_hook_delivery_channel`, `test_ci_lanes`/`LOCAL_COVERAGE` patterns, wire freeze + baseline gate, `fleet_smoke`, walkthrough shape, `gate` aggregation, git-hook chain + leak check, `milestone.md`, PR/issue templates, `fix`/`retro`, `recon.md`.
